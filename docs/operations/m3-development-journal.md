## Engineering approach

The supplied planning, security, test-driven-development, primary-source research, and frontend skills informed the M3 plan:

1. **Vertical slices:** each capability moves from frozen boundary through strict contract, main-owned adapter, narrow IPC/preload seam, accessible component, denial/restart proof, and evidence before the next authority increment.
2. **Threat first:** provenance, links/reparse points, parser ambiguity, collisions, archive/import boundaries, path identity, trust, approval replay/drift, content leakage, and inert-script guarantees are frozen before production implementation.
3. **RED then GREEN:** new authority begins with focused failing tests at an absent seam; the smallest implementation turns only that matrix GREEN while inherited gates remain intact.
4. **Primary sources:** format and platform decisions are checked against authoritative upstream specifications or project documentation and recorded with the evidence that depends on them.
5. **Accessible component seams:** definition surfaces preserve keyboard operation, stable accessible names, focus, live status, narrow layouts, zoom, reduced motion, forced colors, honest empty/error states, and explicit inert/trust labels.

These are reviewable engineering principles, not private chain-of-thought.
